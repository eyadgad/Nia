# Nia

A terminal AI assistant for four published PostgreSQL research lists. Each session remains bound to one list. The frontend uses the backend in process; you run one command rather than starting two servers.

## Install and run

Install Bun 1.4.2 or a compatible 1.4.x release, download this repository, and open a terminal in its root (the directory containing `package.json`). Internet access is required to install dependencies and contact your selected model provider.

```sh
bun install --frozen-lockfile
bun -e "await Bun.write('.env', Bun.file('.env.example'))"
```

Edit `.env` with your PostgreSQL connection, trusted principal, approved tool-capable model ID, endpoint and API key. Then run:

```sh
bun start
```

Choose a list and ask questions naturally. Use `/new` for another list. `bun start --help` shows headless options. `bun start --list 49 "How many students are recorded?"` asks a single question. Existing saved sessions remain under `~/.opencode-research` unless `NIA_STATE` is set.

`NIA_BASE_URL` must be the complete OpenAI-compatible API base URL, usually ending in `/v1`. The simple setup registers only `NIA_MODEL`, enables tools, and uses a 32,000-token context and 4,096-token output limit. For different model limits, reasoning settings or non-compatible providers, set `NIA_PROVIDERS` to a provider JSON file using the existing `package`, `settings` and `models` format. Explicit provider files take precedence over the simple setup. API keys stay in the environment; the temporary provider file contains an environment reference.

## Database

This source download contains no student records, dump, database credentials, access grants, API keys or saved chats. You need an authorized database containing the four research lists and the gateway in `backend/database/gateway.sql`. Your administrator installs that gateway and provisions an account with `opencode_research_ro` and the existing list permissions. Nia does not create live access grants. Keep verified TLS (`NIA_SSL=verify-full`) for remote connections.

For development with the original `postgres-live-2026-10-15.dump`, use Docker plus Bash, `sha256sum` and a compatible PostgreSQL `pg_restore` tool (on Windows use WSL or another Bash environment). The dump is supplied separately and checked against its known fingerprint. Choose a profile path outside this repository:

```sh
bash backend/database/restore.sh /path/to/postgres-live-2026-10-15.dump /path/outside/repository/profile.json
```

The script creates a new isolated `opencode-research-fixture` container, refuses to overwrite an existing one, installs the gateway and creates fixture-only grants. It prints a profile location. Copy that profile's `url`, `principal`, `private`, and `ssl` values into the corresponding `NIA_DATABASE_URL`, `NIA_PRINCIPAL`, `NIA_PRIVATE` and `NIA_SSL` entries in `.env`. Its random port is specific to that container. If Docker runs inside WSL, confirm the published loopback port is accessible from your terminal.

To verify retrieval without a model call, save `{"operation":"count"}` as `count.json` and run:

```sh
bun start --list 49 --query-file count.json --json
```

The supplied Master publication has 2,814 records. A live database may have a newer publication.

## Included code

```text
backend/
  src/          Agent host, retrieval, queries, evidence and research tools
  database/     Read-only gateway and isolated development restore script
  runtime/      Required shared engine, providers, sessions, contracts and SDK
  patches/      Dependency patches referenced by package.json and bun.lock
frontend/
  src/          CLI and terminal interface
  start.ts      Portable environment-based launcher
package.json    Workspace installation and start commands
bun.lock        Pinned third-party versions and local workspace links
.env.example    Configuration template
LICENSE         MIT license and upstream attribution
```

Upload both directories **and the root files** together. `runtime/` contains real source packages, not links to the developer's computer. `node_modules/` is generated by `bun install`; no other source directories are required. Bun executes the included TypeScript directly. This is an application source export; contributor tests, benchmark results and upstream build/release tooling remain in the development repository.

The application enforces its existing read-only gateway, permanent list binding and permission checks. The source export preserves the current application behavior; packaging does not certify that every generated answer is correct.
